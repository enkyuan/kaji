# Product

## Register

brand

## Platform

web

## Users

Backend and product engineers evaluating or integrating `@irogane/kaji`
in a TypeScript application. They need to understand the execution
contract, install the actual npm package, and move from a minimal
capability to authorization, approval, idempotency, and failure
semantics they can rely on.

## Product Purpose

Explain Kaji as an embedded execution layer that safely turns
agent-requested application actions into real state changes, and
provide a trustworthy path from installation through the concepts and
API surface a production integration needs.

## Positioning

Kaji gives application developers one small, embedded execution
boundary for capability-shaped actions in TypeScript, without a hosted
platform, agent framework, or identity system.

## Conversion & proof

- Primary and secondary CTA: install `@irogane/kaji`, then follow
  getting started.
- The line a visitor remembers after 10 seconds: Kaji safely executes
  the actions your agents request.
- Belief ladder: Kaji is embeddable; execution outcomes are explicit
  (`succeeded`/`failed`/`unknown`); idempotency and approval are
  enforced, not merely suggested; the package has zero runtime
  dependencies.
- Proof on hand: the published `@irogane/kaji` package and the
  `examples/refund` proof example in the repository.

## Brand Personality

Precise, quiet, and hand-crafted. The documentation should feel like a
careful technical notebook rather than a generic product template.

## Anti-references

Avoid dashboard chrome, oversized SaaS marketing sections, decorative
card grids, and documentation themes that obscure the reading flow.
Agentation is the explicit visual and interaction reference.

## Design Principles

- Put readable, copyable technical content first.
- Let the implementation demonstrate the product's bounded, inspectable character.
- Keep navigation compact and predictable.
- Preserve one visual voice from overview through deep reference pages.
- Use interaction only where it removes friction.

## Accessibility & Inclusion

Support keyboard navigation, visible focus, semantic landmarks, readable
contrast, responsive layouts, and reduced-motion preferences.
