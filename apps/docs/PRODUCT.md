# Product

## Register

brand

## Platform

web

## Users

Backend and product engineers adding autonomous or agent-requested writes and
external effects to an existing TypeScript application. They need to
understand the execution contract, install the package, and govern one
capability end to end: validation, authorization, approval, idempotency, and
explicit outcomes.

## Product Purpose

Explain Kaji as an embedded execution layer that safely turns agent-requested
application actions into real state changes, and provide a trustworthy path
from installation through the frozen v0 contract.

## Positioning

Kaji gives application developers one small, framework-neutral execution
boundary for capabilities that agents, MCP tools, workflows, or direct
application code can request — without becoming an agent framework, workflow
engine, or hosted platform.

Kaji v0 is TypeScript-only and pre-1.0. It ships no model providers, no agent
loop, no tool registry, no CLI, and no integration catalog. Python and Go are
later scaffolds and do not expand the v0 API.

## Conversion & proof

- Primary and secondary CTA: read the getting-started guide, then define one
  capability.
- The line a visitor remembers after 10 seconds: safely turn an
  agent-requested action into a real side effect.
- Belief ladder: Kaji is a library, not a platform; the execution path is
  small and singular; ambiguous outcomes are preserved instead of guessed at;
  the public API is intentionally frozen and small.
- Proof on hand: `docs/api.md`, `docs/invariants.md`, and the runnable
  `examples/refund` proof in the repository.

## Brand Personality

Precise, quiet, and hand-crafted. The documentation should feel like a careful
technical notebook rather than a generic product template.

## Anti-references

Avoid dashboard chrome, oversized SaaS marketing sections, decorative card
grids, and documentation themes that obscure the reading flow. Agentation is
the explicit visual and interaction reference.

## Design Principles

- Put readable, copyable technical content first.
- Let the implementation demonstrate the product's small, inspectable
  character.
- Keep navigation compact and predictable.
- Preserve one visual voice from overview through deep reference pages.
- Use interaction only where it removes friction.

## Accessibility & Inclusion

Support keyboard navigation, visible focus, semantic landmarks, readable
contrast, responsive layouts, and reduced-motion preferences.
