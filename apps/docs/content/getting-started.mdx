---
title: Getting Started
description: Define a capability, create the Kaji executor, and run your first governed execution.
---

This guide builds the smallest complete capability: a payment refund that
Kaji validates, authorizes, and executes exactly once.

<Steps>
  <Step>
    ### Install

    ```bash
    npm install @irogane/kaji zod
    ```

    Zod is one example of a [Standard Schema](https://standardschema.dev)-compatible
    validator. Kaji does not require it.

  </Step>

  <Step>
    ### Define the input schema

    Kaji accepts any validator whose schema exposes `parse(input): Output`
    and throws on invalid input. Validated output is what your capability's
    hooks and `execute()` receive.

    ```ts
    import { z } from "zod";

    const RefundInput = z.object({
      paymentId: z.string().min(1),
      amount: z.number().positive(),
    });
    ```

  </Step>

  <Step>
    ### Define the capability

    A capability wraps one application action. Authorization and the side
    effect stay in your code; Kaji only calls them at the right time.

    ```ts
    import { capability } from "@irogane/kaji";

    const refund = capability({
      name: "payments.refund",
      input: RefundInput,

      authorize: async ({ principalId, input }) => {
        return canRefund(principalId, input.paymentId);
      },

      approval: ({ input }) => input.amount >= 500,

      execute: async (input, context) => {
        return payments.refund({
          ...input,
          idempotencyKey: context.idempotencyKey,
          signal: context.signal,
        });
      },
    });
    ```

    `canRefund()` and `payments.refund()` are your own application code.
    See [capabilities](/docs/concepts/capabilities) for what each field owns.

  </Step>

  <Step>
    ### Create the executor

    `createKaji()` needs an `ExecutionStore` and, if any capability can
    require approval, an `approve` handler.

    ```ts
    import { createKaji, memoryStore } from "@irogane/kaji";

    const kaji = createKaji({
      store: memoryStore(),
      approve: async () => ({ approved: true }),
    });
    ```

    `memoryStore()` is process-local and not durable. See
    [custom store](/docs/guides/custom-store) before deploying to
    production.

  </Step>

  <Step>
    ### Execute

    Every execution needs a caller-supplied `principalId` and
    `idempotencyKey`. Kaji never infers either value.

    ```ts
    const result = await kaji.execute(refund, {
      input: {
        paymentId: "pay_123",
        amount: 750,
      },
      principalId: "user_123",
      idempotencyKey: "refund_req_123",
    });

    if (result.status === "succeeded") {
      console.log(result.result);
    }
    ```

    `result.status` is one of `succeeded`, `denied`, `rejected`, `failed`,
    `cancelled`, or `unknown`. See [execution outcomes](/docs/concepts/outcomes)
    for what each one means and [idempotency](/docs/concepts/idempotency)
    for what happens if you call `execute()` again with the same key.

  </Step>
</Steps>
