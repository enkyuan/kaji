Kaji is a TypeScript library that runs inside your application. It puts one execution boundary in front of application actions that can create side effects.

Use Kaji when an agent, automation, or other caller can trigger functions such as `refundPayment()` or `cancelBooking()`.

## What Kaji governs

Kaji validates input, claims an idempotency key, checks authorization, requests approval when required, executes the capability, and records the result.

Kaji applies this order every time. Callers cannot select a different order through the public API.

## What your application owns

Your application defines each capability. It also owns caller identity, authorization policy, approval policy, the production store, provider calls, and recovery for `unknown` results.

Kaji does not replace these systems. It gives them one consistent execution boundary.

## Result model

Every governed request returns one of six statuses:

- `succeeded`
- `denied`
- `rejected`
- `failed`
- `cancelled`
- `unknown`

Read [Outcomes](/docs/concepts/outcomes) before you add retries or recovery logic.

## Guarantees depend on the store

The configured `ExecutionStore` coordinates claims and recorded outcomes.

`memoryStore()` works only inside one process. It has no persistence, cross-process coordination, or restart durability.

Kaji does not claim globally distributed exactly-once execution. Your store and external provider determine the full guarantee.
