---
title: Kaji
description: Kaji is an embedded execution layer that safely turns agent-requested application actions into real state changes.
---

Kaji standardizes the boundary between a requested action and its execution.
An agent, MCP tool, or any automated caller proposes an action; your
application defines what that action means; Kaji governs how it is safely
executed.

```text
agent/framework/direct caller
        ↓ proposes action
      Kaji
        ↓ governs execution
application capability
        ↓
application/external system
```

Kaji is not an agent framework, workflow engine, tool framework, integration
platform, or generic orchestration system. It has no model providers, no
sessions or event log, no tool registry, and no CLI. It is a small library
you call directly from a TypeScript backend.

## What Kaji governs

Given a **capability** — one named application action such as
`payments.refund` — Kaji's executor validates input, identifies the caller,
authorizes the request, obtains approval when required, calls the
capability at most once, and records an explicit outcome:

- input validation before any authorization or side effect
- a caller-supplied idempotency key so retries and duplicates don't re-run
  the action
- an optional human approval boundary for high-risk actions
- cooperative cancellation and timeout through native `AbortSignal`
- an honest `unknown` outcome when a side effect may have happened but
  completion can't be proven

## What Kaji does not provide

Kaji v0 is TypeScript-only and deliberately small. It does not provide LLM or
model providers, agent loops or planning, workflow orchestration or retry
scheduling, an MCP server or tool registry, sessions or event sourcing, a
hosted control plane, or an identity/authorization system. Those stay with
your agent framework and your application. See `docs/product.md` in the
repository for the full non-goal list.
