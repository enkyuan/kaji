Kaji is an embedded execution layer for safely turning agent-requested
application actions into real state changes. It is a TypeScript library,
not a hosted service: it runs inside your application process and adds
no network dependency, database, or control plane of its own.

## Where Kaji sits

```text
agent / framework / direct caller
            ↓
           Kaji
            ↓
   application capability
            ↓
 application / external system
```

Your application already has functions like `refundPayment()`,
`cancelBooking()`, or `sendEmail()`. When something outside your direct
control — an agent, an automation, an MCP tool call — can trigger one of
those functions, each caller would otherwise need to solve caller
identity, input validation, authorization, human approval, idempotency,
and ambiguous side effects on its own. Kaji standardizes that boundary
once, in your application, instead of once per caller.

## What Kaji is not

Kaji does not provide:

- an agent framework, model SDK, or agent loop
- a workflow engine or task scheduler
- an MCP runtime or tool registry
- an identity provider or authorization system
- a queue or retry engine
- event sourcing or a general event bus

Your application supplies identity, authorization policy, and the
domain logic behind each action. Kaji only governs how a request to run
that action is validated, authorized, approved, executed once, and
recorded.

## Core exports

```ts
import { capability, createKaji, knownFailure, memoryStore } from "@irogane/kaji";
```

- [`capability()`](/docs/concepts/capabilities) declares one application action.
- [`createKaji()`](/docs/reference/api#createkaji) creates the executor that runs capabilities.
- [`knownFailure()`](/docs/concepts/outcomes#knownfailure) marks a definitively known, non-ambiguous failure.
- [`memoryStore()`](/docs/guides/custom-store) is the process-local reference `ExecutionStore`.
