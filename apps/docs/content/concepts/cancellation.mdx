---
title: Cancellation
description: Use `AbortSignal` for cooperative cancellation without assuming rollback or forced termination.
---

Kaji uses the platform `AbortSignal`. It does not add a custom cancellation token.

A capability receives the effective signal through `ExecutionContext`:

```ts
execute: async (input, context) => {
  return provider.refund(input, {
    idempotencyKey: context.idempotencyKey,
    signal: context.signal,
  });
},
```

## Before capability execution

Kaji checks the signal before these steps:

1. input validation
2. the store claim
3. authorization
4. approval
5. capability execution

When the signal is already aborted at one of these checks, Kaji returns `cancelled`. It does not call the capability.

Cancellation before the store claim has no execution record. Cancellation after the claim is recorded when the store remains available.

## Post-execution

After Kaji calls `execute()`, cancellation is cooperative. Kaji cannot forcibly terminate application code or a remote request.

The capability or downstream API must observe `context.signal` for cancellation to interrupt work.

If `execute()` rejects after the signal aborts, Kaji returns `unknown`. The side effect can commit before the rejection reaches Kaji.

If `execute()` ignores the signal and later resolves, Kaji can return `succeeded`.

## `timeoutMs`

```ts
const kaji = createKaji({
  store: memoryStore(),
  timeoutMs: 30_000,
});
```

`timeoutMs` aborts the effective signal after the configured duration.

When the caller also supplies a signal, Kaji combines both signals with `AbortSignal.any()`. The first signal to abort controls the effective signal.

Kaji continues awaiting `execute()` until it settles. Therefore, `timeoutMs` does not bound the wall-clock duration of capability execution.

A timeout does not prove rollback. It does not prove that a remote operation stopped or failed.

## Handle an abort

Pass `context.signal` to downstream APIs that support cancellation. For custom work, check the signal at safe points.

```ts
execute: async (input, context) => {
  context.signal.throwIfAborted();
  return provider.refund(input, { signal: context.signal });
},
```

Do not convert a post-start abort into `knownFailure()` unless application code proves that no side effect committed.
