---
title: Idempotency
description: Use execution identities and input fingerprints to prevent duplicate capability calls.
---

Every execution request includes a caller-supplied `idempotencyKey`.

```ts
await kaji.execute(refundPayment, {
  input: { paymentId: "pay_123", amount: 50 },
  principalId: "user_123",
  idempotencyKey: "refund_pay_123_v1",
});
```

## Execution identity

Kaji identifies the intended operation with:

- the capability name
- `principalId`
- `idempotencyKey`

Kaji also fingerprints the validated input.

Use one key for one intended operation. Use the same key only when you retry that same operation.

## First claim

The store returns `status: "claimed"` for a new identity. Kaji then checks authorization, requests approval when required, and can execute the capability.

The claim operation must be atomic. Concurrent callers for the same identity cannot both receive a new claim.

## Identical duplicate

The store returns `status: "existing"` when the identity and input fingerprint match an active or recorded claim.

The duplicate caller waits for or receives the same recorded outcome. Kaji does not call the capability again.

This behavior also applies to recorded `unknown` outcomes. A retry does not turn `unknown` into `succeeded` or `failed`.

## Conflicting duplicate

The store returns `status: "conflict"` when the identity matches but the validated input fingerprint differs.

Kaji returns `status: "failed"`. It does not call the capability with the conflicting input.

## Guarantee scope

Kaji coordinates duplicates through the configured `ExecutionStore`.

`memoryStore()` coordinates only callers inside one process. A restart removes its records, and another process cannot see its claims.

A durable shared store can provide broader coordination. Its exact guarantee depends on its atomic claim and persistence behavior.

Kaji does not claim globally distributed exactly-once execution.

## External providers

Kaji prevents a duplicate capability call for one stored claim. It cannot control what an external provider does inside that call.

Pass `context.idempotencyKey` to the provider when possible:

```ts
execute: (input, context) =>
  provider.refund(input, {
    idempotencyKey: context.idempotencyKey,
    signal: context.signal,
  }),
```

Provider idempotency and reconciliation remain application responsibilities.
