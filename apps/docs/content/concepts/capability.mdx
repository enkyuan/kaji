---
title: Capabilities
description: Define one validated, authorized application action.
---

A capability describes one application action that Kaji can govern.

```ts
const refundPayment = capability({
  name: "payments.refund",
  input: RefundInput,
  authorize: ({ principalId, input }) => canRefund(principalId, input),
  approval: ({ input }) => input.amount >= 1_000,
  execute: (input, context) => refundThroughProvider(input, context),
});
```

## `name`

`name` must be a non-empty string. Use a stable name that identifies the application action.

The name forms part of the execution identity and input fingerprint. Renaming a capability changes those values.

## `input`

`input` must provide a `parse(input)` method. The method returns validated input or throws.

Kaji passes the parser result to `authorize`, `approval`, and `execute`. These functions never receive the original unvalidated value.

Kaji has no runtime dependency on Zod or another validation library.

## `authorize`

`authorize` receives the caller-supplied `principalId` and validated input.

It can return a boolean or a promise of a boolean. A `false` result or thrown error returns `status: "denied"` and prevents capability execution.

Read [Authorization](/docs/concepts/authorization) for policy boundaries and failure behavior.

## `approval`

`approval` is optional. It receives the same principal ID and validated input.

When it returns `true`, Kaji asks the executor's `approve` handler for a decision. The predicate itself is synchronous in the current public API.

Read [Approval](/docs/concepts/approval) for the full contract.

## `execute`

`execute` receives validated input and an `ExecutionContext`:

```ts
export type ExecutionContext = {
  readonly principalId: string;
  readonly idempotencyKey: string;
  readonly signal: AbortSignal;
};
```

Use `context.idempotencyKey` when the external provider supports idempotency. Observe `context.signal` when the provider supports cancellation.

A successful return produces `status: "succeeded"`. A normal thrown error produces `status: "unknown"` after execution begins.

Throw `knownFailure(cause)` only when application code knows that no side effect committed.

## Capability objects

`capability()` validates its declaration and returns a frozen object. The public `Capability<Input, Result>` type exposes only `name`.

Kaji retains the full declaration internally. Callers execute the capability through `kaji.execute()` rather than calling its functions directly.
